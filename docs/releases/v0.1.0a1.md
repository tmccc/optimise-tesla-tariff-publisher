# v0.1.0a1 — experimental technical preview

First tagged prerelease of the standalone Optimise → Tesla tariff publisher.
This is intended for technically experienced testers with their own activated
Optimise account, Home Assistant installation and Tesla energy system.

## Included

- Paired import/export tariffs compiled from the separate read-only
  [E.ON Next Optimise HA integration](https://github.com/tmccc/ha-eon-next-optimise).
- A recurring publisher, two-minute checks and no-POST lease renewal when prices
  are unchanged.
- A separate watchdog, short safety leases, guarded Self-Powered fallback and
  separately approved Savings enable/recovery.
- Durable command intents, readback/ownership checks and persistent pauses for
  manual changes or E.ON battery-control handover.
- Token-bound, expiring permission caching to reduce repeated scope lookups.
- User-service templates for automatic process recovery and startup at boot.
- Optional Home Assistant examples for failed prices, Self-Powered mode and
  sustained net-export notifications.

## Install

Follow the [installation walkthrough](https://github.com/tmccc/optimise-tesla-tariff-publisher/blob/v0.1.0a1/docs/installation.md). It covers
the local gateway reader and Tessie dependencies, private configuration,
read-only preparation, explicit activation and safe stopping order.
The repository's approval and live-execution examples remain disabled by default.
The publisher is a standalone application; it is not installed through HACS.

Requires Python 3.11 or newer on Linux/POSIX, a compatible local gateway reader,
configured HA source entities, and Tessie API access with energy read/command
permissions. Current command transports require one eligible battery energy site
on the account. The separate HACS integration has its own version numbers.

## Validation and limits

The existing offline suite passes 489 tests and runs in GitHub Actions on
Python 3.11–3.14. One live installation exercised paired-price publication,
saved configuration readback, actual gateway mode, watchdog expiry, fallback,
recovery and automatic process restart. Boot enablement was checked without
rebooting that host. The fresh-install procedure still needs independent testing
on other systems and account types.

**Not established:** which stored tariff representation Tesla's planning engine
consumed, sustained automatic export, bill savings, or broad hardware/account
compatibility. Read the [conflicting tariff readback evidence](https://github.com/tmccc/optimise-tesla-tariff-publisher/blob/v0.1.0a1/docs/tesla-tariff-readback-evidence.md).

Negative prices and import prices below export prices are rejected because
Tesla's manual tariff API can adjust them. Unquoted periods use an explicitly
approved current-pair planning assumption, not genuine future quotes. A host,
network or provider outage can prevent fallback; the tariff has no documented
firmware-enforced expiry. No reserve or grid/export-permission changes are made
by the publisher. Other active battery controllers must be considered before
opting into this temporary arrangement.

This does not repair Tesla/Flatpeak supplier linking, enrol a battery with E.ON,
or imply endorsement by E.ON, Amber, Tesla, Tessie, Home Assistant or HACS.
